# Vector Siege Campaign Contract

## Candidate-Safe Assignment

Build Vector Siege as the staged TypeScript, Vite, Phaser 4 browser arena shooter
defined by issue #545. Candidate implementation starts only in an approved later
phase from one frozen minimal scaffold and one frozen standardized asset bundle.

## Phase 0A Scope

Phase 0A validates only:

- tracked campaign freeze state;
- deterministic placeholder MP3, WAV, WebP, palette, atlas, and manifest files;
- pinned Draft 2020-12 schema validation;
- provider-credential removal and bounded no-network/no-child-process controls;
- the explicit `phase_0b: blocked` state.

No candidate prompt, runtime adapter, model invocation, game implementation,
deployment, provider mutation, polished media generation, or policy amendment is
part of Phase 0A.

## Phase 0B Boundary

The prepared feasibility campaign has five matched counterbalanced Stage 1
repetitions each for Arms A and B using Codex `gpt-5.6-luna` at `max` effort.
The frozen order is `AB`, `BA`, `AB`, `BA`, `AB`, with candidates executed
sequentially. Candidate defects receive no retry; verified provider-transient or
harness failures receive at most one retry.

Preparation validates the scaffold and emits a blocked run plan. It does not
create the frozen remote base or execute candidates. Those operations require a
later explicit maintainer approval.

Gate 0 requires all ten assignments to reach a terminal state, complete required
telemetry for every assignment, at least 90% harness reliability, and at least
two Arm B fan-out elections. Missing a threshold is a no-go or revision result,
not permission to weaken the threshold after observing outcomes.
