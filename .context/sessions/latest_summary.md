## Generalizable Lessons
- **The "one coherent commit per round" rule should be interpreted as "one coherent commit per ROOT CAUSE per round", not "one commit per ISS-NN".** Round 1 of this PR consolidated 14 ISS items into a single commit because all 14 derived from the same root cause (the canonical/overlay split from the underlying refactor) — splitting them into 14 commits would have been needless ceremony and made the diff harder to review. The cap-override justification "legitimate refactor" is the right framing for this. The `pr-resolve-all.md` rules say "fix-only commits"; they don't mandate one-item-per-commit when items share a refactor lineage. (See ADR-022 / cap-override convention.)
- **Bot reviewers re-fire on every push and tend to surface the same finding on slightly different lines** as the diff evolves. R5 + R6 + R7's parity-script gemini findings are an example: each round, gemini surfaced a slightly-tightened version of "make the regex more robust" — first `grep -F`, then quote-style, then trailing-whitespace, then anchoring. The right pattern is: apply the substantive fix, document the heuristic limitation in-code (ISS-25 added a 16-line comment explaining the design choice), and **defer further regex-tightening pushback** with a citation to the documented design choice. R7's defer ("over-anchor regex; gemini conceded 'currently safe'") is the case-in-point — bots will accept a defer when you cite their own concession.
- **ADR-023's overlay-as-pointer is a contested architectural choice that gets re-litigated by reviewers.** Codex flagged it twice (R1 ISS-17, R4 ISS-26) as "automation still consumes the overlay body directly, so stripping the body degrades behavior." Both findings had a *valid sub-finding* (specific consumers reading the overlay path) which we fixed (ISS-15 + ISS-26 migrations to canonical), but the *architectural disagreement* was deferred. The pattern that worked: split the codex finding into "valid concrete bug → fix" + "architectural disagreement → defer with ADR-023 link", and the loop converged. Pure-architectural disagreements without a cited concrete bug should always defer; pure-concrete bugs without an architectural axe to grind should always fix.
